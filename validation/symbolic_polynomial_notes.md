# Symbolic Polynomial Notes

These notes summarize the exact-computation evidence generated by
`validation/polynomial_degree_extended.py` and
`validation/rho_infinity_investigation.py`. They are working notes, not a
artifact proof.

## Setup

For a compositional OSDS cap, the body contains `L` READ operations and `m` OBS
operations. With positive default parameters, the maximum output occurs when all
OBS operations precede all READ operations, and the minimum occurs when all OBS
operations follow all READ operations. The finite-grid script checks this
extremal-order formula against exhaustive permutation enumeration for `m=1..4`,
`d=1..5`, and `L=2..15`.

Let `delta` denote the per-access entropy increment and `eta` the OBS entropy
increment. The OSDS body-range term is

```text
Delta_y_OSDS = eta * m * L(L - 1) / 2.
```

The compositional cap contributes `d-1` final reads of `x`. The `r`th final read
has the form

```text
base + (L + r) * (1 + delta * L + eta * m + delta * r).
```

Each cap factor is quadratic in `L`. Therefore the checked algebra indicates
that the OSDS divergence degree is

```text
2 + 2(d - 1) = 2d.
```

This explains why the previously convenient `d+2` form agrees at `d=2`, but it
does not agree for `d=1` or `d>=3` under the current compositional-degree
parameterization.

## Rho Infinity

For the generalized compositional runtime model used in
`validation/rho_infinity_investigation.py`, OBS advances runtime access state by
the same per-access increment `delta`. The runtime body-range leading term is

```text
Delta_y_runtime leading coefficient = delta * m.
```

The OSDS body-range leading coefficient is

```text
Delta_y_OSDS leading coefficient = eta * m / 2.
```

The final cap factors have the same leading coefficient in both models:
`delta^(d-1)`. These leading cap factors cancel in the ratio. The resulting
candidate limit is

```text
rho_infinity = eta / (2 * delta).
```

With the default parameters `eta=1` and `delta=1/10`, this gives
`rho_infinity=5`.

## What Is Complete

- The generated CSV files use exact rational arithmetic.
- The OSDS extremal-order formula is checked against exhaustive permutation
  enumeration on the stated finite grid.
- The interpolation holdout checks pass exactly on the stated finite grid.
- The leading-coefficient cancellation explains the observed default
  `rho_infinity=5` in the external generalized compositional runtime model.

## What Is Incomplete

- The finite-grid exhaustive checks are not a proof for all `L`, `m`, and `d`.
- The extremal-order argument is not formalized as an induction over all
  permutations.
- The generalized runtime formula for compositional `d=4..5` is external to the
  historical helper and should not be described as interpreter validation.
- The data do not support an unqualified `d+2` polynomial-degree theorem for the
  current compositional-degree parameterization. A corrected theorem would need
  either a revised degree definition or a revised statement, likely involving
  the observed `2d` degree.

## Conservative Status

The strongest justified statement from these scripts is computational:

```text
For checked compositional OSDS cases m=1..4 and d=1..5, exact finite-grid
enumeration plus extremal-order interpolation detects degree 2d, not d+2 except
when d=2.
```

The `rho_infinity=5` observation is now explained by an exact leading-term
cancellation under default parameters, but should still be framed as a proof
sketch unless the extremal-order and generalized-runtime assumptions are
formalized.
