\begin{abstract}
Access-induced semantic divergence occurs when an operation that appears observational updates latent access state and changes a later externally visible result. We model this pattern as an observation-sensitive deterministic system (\osds), prove structural properties for a restricted straight-line core, and use the model to build real-package witnesses and OSDS-aware replay checks. The real-code study confirms 20 divergences across 12 unmodified Python packages, with 9 caller-level branch effects and 19/19 applicable mechanism controls eliminating divergence. In a frozen generated-transformation benchmark, five model-task outputs over two underlying package witnesses produced verified OSDS divergence. Ordinary benchmark checks missed all five; OSDS-aware verification caught all five; exact replay reproduced all five; and mechanism-neutralizing controls removed all five while the generated candidate stayed fixed. A prospectively frozen expansion from 7 additional confirmed witnesses produced 42 outputs: 23/42 were task-compliant transformations, 19/42 returned unchanged code, 23/23 compliant transformations preserved OSDS behavior, and 0/42 produced verified OSDS divergence. The results support a bounded conclusion: generated transformations can silently violate access-sensitive semantics on validated witnesses, and a mechanism-specific OSDS model with replay and causal controls provides a verifiable method for detecting and attributing this failure mode.
\end{abstract}
